# Проверки

Живые проверки интерфейса: настоящий `index.html` открывается в headless-браузере,
подменяется единственная дверь наружу (клиент Supabase или `_giFetch`), дальше
работает тот же роутер, та же отрисовка и те же обработчики, что и в бою.

## Как запускать

```bash
./tests/run.sh            # всё
./tests/run.sh calc zen   # только probe_calc.js и probe_zen.js
```

Скрипт сам поднимает статику на `127.0.0.1:8897`. Нужен Node и Playwright
(`chromium`); путь к нему прописан в первой строке каждого файла.

## Правила

**Ожидаемое значение считается на бумаге и вписывается числом.** Не «то, что
вернул код в прошлый раз» — иначе проверка охраняет ошибку. Исключение —
`golden_calc.json`: это слепок расчётов, снятый с проверенной версии ядра, и
нужен он для одного — доказать, что правка интерфейса не сдвинула ни одной
цифры. Формулы в нём не проверяются, для этого есть остальные проверки.

**Название проверки — утверждение о продукте, а не о коде.** «ROAS ниже
безубыточного — в минус», а не «verdictRoas returns bad».

**Падение — это находка.** Прежде чем править проверку, убедитесь, что ошибается
именно она, а не продукт.

## Что где

| Файл | О чём |
|---|---|
| `probe_calc.js` | Маркетинговый калькулятор: формулы, воронка, сценарии, план-факт |
| `probe_design.js` | Дизайн-система калькулятора: шкалы, фокус, движение, раскладка |
| `probe_pfin.js` | Финансы проекта |
| `probe_pks.js` | Статистика проекта |
| `probe_zen.js` | Доска, полноэкранный режим |
| `probe_client.js` | Клиентский кабинет |
| `probe_empwin.js` | Окно сотрудника: раскладка, навигация, каскад прав, вход |
| `probe_tariff.js` | Тарифы и продления |
| остальные | Задачи, материалы, согласования, всплывашки, дедлайны |
